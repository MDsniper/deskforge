# Local AI GPU Comparison

A responsive, client-side comparison website for GPUs used in local large-language-model workloads. The site includes consumer, professional workstation, and data-center accelerators, with filtering by minimum dedicated VRAM and maximum acquisition price.

## Features

The page compares VRAM and memory type, bandwidth, board power, cooling and form factor, CUDA/ROCm/oneAPI ecosystem considerations, training suitability, inference suitability, and approximate price/value. It includes Blackwell consumer GPUs, RTX PRO workstation cards, AMD Radeon AI PRO, Intel Arc Pro, H200, and B200 entries.

The site is fully static. It has no API keys, database, server-side runtime, or external JavaScript dependencies. GPU data is embedded in `index.html` so it can be deployed as a simple Docker container.

## Amazon Associates links

Each GPU row includes a **Check Amazon** button. The button is generated by `amazonSearchUrl()` and opens an Amazon search for the GPU model, which is more reliable than hard-coding a single board-partner product page. The links use `rel="sponsored nofollow noopener"`.

Before publishing, replace `YOUR-AMAZON-TAG-20` near the top of the script in `index.html` with the tracking ID issued for the correct Amazon Associates marketplace. The helper only appends a `tag` parameter when the value matches the normal Associates format; with the placeholder still present, it generates an untagged search URL for testing. Do not insert API keys or secret credentials into this static site.

Keep the disclosure visible on the page and review Amazon Associates Operating Agreement requirements, price-display rules, trademark rules, and the policies for your target marketplace before activating monetization.

## Run locally

Using Docker:

```bash
docker compose up --build
```

Open `http://localhost:8080`.

Without Docker, open `index.html` in a browser or serve the directory with any static web server.

## Deploy with GitHub and Dokploy

Create a GitHub repository and push the contents of this directory:

```bash
git init
git add .
git commit -m "Create local AI GPU comparison site"
git branch -M main
git remote add origin https://github.com/YOUR-ACCOUNT/YOUR-REPOSITORY.git
git push -u origin main
```

In Dokploy, create a new **Application** and select the GitHub repository. Use the repository root as the build context. Select **Dockerfile** as the build type and set the Dockerfile path to `Dockerfile`. Expose container port `80`. If using the included Compose file instead, create a **Compose** deployment and use `docker-compose.yml`; Dokploy can publish the service through its domain and HTTPS configuration.

For a Dockerfile deployment, the application does not need an environment variable. Configure the domain in Dokploy, enable HTTPS, and deploy. The container has an Nginx health check at `/healthz`.

## Updating GPU data

Edit the `gpus` array in `index.html`. Each item should contain the fields `model`, `line`, `vram`, `memory`, `bandwidth`, `power`, `cooling`, `software`, `training`, `inference`, `price`, `priceText`, `value`, and `source`. Commit and push the change; Dokploy can redeploy automatically when GitHub webhook deployment is enabled.

Prices are research snapshots and should be rechecked before publication. Enterprise accelerator prices are frequently quote-based. The site deliberately labels such values as market estimates rather than guaranteed retail offers.
